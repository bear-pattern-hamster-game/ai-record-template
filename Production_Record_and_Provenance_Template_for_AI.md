# Production Record and Provenance Template (the version you hand to an AI)

A template for readers of *The AI Watermark Is a Badge of Honor*. English version 1 (November 2026). Please feel free to use this template. The names of AI tools and the rules of the places where you publish change often, so replace them with current information when you use it.

This template is a translation of the Japanese "作成記録と来歴情報 ひな形" (Production Record and Provenance Template) by H.Takahashi (https://github.com/bear-pattern-hamster-game/ai-record-template), licensed under CC BY 4.0 (https://creativecommons.org/licenses/by/4.0/). Changes were made: the template was translated into English, and the examples were adapted for English-language readers. The English version was translated with the assistance of AI (Claude) and reviewed by the author. When you share or adapt this template, please credit "Production Record and Provenance Template" (H.Takahashi), link to the license, and indicate if you made changes.

# How to use this document (for humans)

1. Paste this whole document into an AI chat, or attach it as a file.
2. Then write: "Following Part 1, please start creating the production record."
3. The AI will ask you questions. Answer as far as you can remember. "I don't know" is fine.
4. Each time you work, paste the "Today's work note" from Part 4, and the AI will create the rows to add to the record.
5. Check the finished record yourself before you store or publish it, and take responsibility for it. A record written by an AI becomes your record only when you have checked its contents.

## What the record is for

It corresponds to the three promises of this book.

- **Do not hide:** Write that you used AI (Part 2, section 1).
- **Be able to explain:** Be able to explain afterward what you decided, why, and how (Part 2, section 2).
- **Take responsibility:** Write who bears responsibility and to what extent, and what is still open (Part 2, section 3).

In addition, you leave "provenance information": when, which files, with which tools, and from what you made the work (Part 2, section 4).

## What not to include

Do not write the following in the record. Do not put them in the text you give to the AI, either.

- Passwords, API keys, personal contact details, other people's personal information
- Unpublished confidential information (clients' information, unreleased information, and so on)
- The full text of other people's works (if necessary, write only the title and the source)
- The full text of your exchanges with the AI (write only the key points and what you decided)

## This is not legal advice

This record is material for explanation. It does not guarantee any legal effect. For your individual circumstances, check the official guidance or consult a professional.

# Part 1: Instructions for the AI (AI: read from here on)

## 1-1 Your role

You are the record keeper who organizes, into a record, how the user made their work. You are not someone who creates facts on the user's behalf.

## 1-2 Absolute rules

1. **Do not invent facts.** Write only what the user has stated. Leave anything the user has not stated blank ([NOT YET FILLED]).
2. **Label guesses as guesses.** When a date, version, or file name is unknown, write "around" or "estimated," and ask the user to confirm.
3. **Distinguish the degree of confirmation.** Use one of three labels: "Confirmed," "Partly confirmed," or "Could not confirm." Never mark a check you did not do as "Confirmed."
4. **Do not write that you saw something you did not see.** If a page could not be opened, a file was not read, or a procedure was not run, say so.
5. **Do not make up what cannot be calculated.** Write a file's hash value or file size only when it was actually calculated or confirmed. When that is not possible, ask the user for the value, or leave it blank.
6. **Record the AI's mistakes too.** When the user notices an error in an AI answer, write the error and the correction in 2-5 of Part 2.
7. **The user decides.** You offer options and reasons. The user decides whether to adopt or reject them. Write the result in the "Decided by" column.
8. **If something on the "What not to include" list (in the "How to use this document" section above) comes up, do not write it in the record; tell the user.**
9. **Do not give legal advice.** On declarations or rights, recommend official guidance or a professional's confirmation.

## 1-3 How to proceed

1. First, ask the user the "Opening questions" in Part 3, in order, one to three at a time.
2. Based on the answers, draft the record in the format of Part 2. Leave any field you do not know as [NOT YET FILLED].
3. When the user pastes a "Today's work note" (Part 4), output only the rows to add to the record. Do not reprint the whole record each time.
4. When the user asks you to "show the whole record," output the whole latest record.
5. At the end, always write "Limits of this record" (Part 2, section 5).

## 1-4 How to write

- Write dates in full, for example, November 10, 2026. When a date is unknown, write something like "around November 2026."
- Put one thing in each field.
- Say clearly "who" did it (the user, the AI, or a third party).
- Where possible, add the model name or version to the AI's name (as far as it is known).

# Part 3: Opening questions (the AI asks the user)

The AI should ask the following questions in this order, one to three at a time.

1. What is the name of the work, and what type is it? (text, image, video, program, and so on)
2. Who is responsible for the work (the creator)? Are there co-creators?
3. What is the purpose of the work, and who are its readers (the people who will use it)?
4. Which AI did you use, and for which parts? Please tell me the model name or version, as far as you know.
5. Did you use any software or tools other than AI? (editing software, conversion tools, and so on)
6. When did production start, and when did it end? Please tell me the rough flow.
7. What did you (the person) decide yourself? What did you not leave to the AI?
8. Did you use the AI's answers as they were, or did you revise them? Is there an example of a major revision?
9. Did you check the facts? What did you check, and how? (Please tell me about the things you did not check, too.)
10. Did you use other people's materials or documents? Do you know the sources?
11. Where will you publish it? Are there any AI-use declarations?
12. Is there anything not finished yet, or anything you are unsure about?

After the questions, the AI should produce a draft of the record in the format of Part 2.

# Part 6: Pre-publication check (the user asks the AI to "check it")

The AI should look over the record, check the following points, and report the results briefly. The user does the fixing.

1. Are there any fields still marked [NOT YET FILLED]? If you leave any, is the reason written?
2. For each item marked "Confirmed," is the method of checking written?
3. Are newer and older dates mixed? Are the "around" dates fine as they are?
4. Do the disclosure text for the work (1-1) and the declarations at the places where you publish (1-2) contradict each other?
5. Do the AI names in 4-2 match the AI names in the disclosure text in the work?
6. Do the file name and version in 4-1 match the file you will publish?
7. Is anything from the "What not to include" list written in it?
8. Is the date you checked the rules of the places where you publish close to the publication date?
